The quasistatic MEMS drive path

Quasistatic is the one MEMS mode that accepts an arbitrary analog X/Y signal — the kind reactoscope's Master Output already is. This traces that path stage by stage through the libraries in mems/, with the real numbers each one uses, and asks what a quasistatic MEMS Scanner Model would actually have to compute. Companion to the MEMS mirror survey.

Finding 1

The units already match. Mirrorcle's analog input is bipolar, zero-centred, ±10 V with origin at 0 V, and every control library in this set normalizes to [-1, +1] first — the same convention as reactoscope's X/Y.

Finding 2

The bandwidth does not. The driver's own spec is 50–25,000 Hz, but the in-path anti-resonance filter is set per mirror to 220–500 Hz in practice — roughly 1–2% of the audio band.

Finding 3

A mandatory 5th-order Bessel low-pass (MAX7413) sits between input and mirror, tuned by an external clock at exactly 60× the cutoff. Stop the clock and the output stops following the input entirely.

Finding 4

That filter is the slew limit. A galvo model needs a separate slew clamp because a linear filter makes long jumps free; here the band limit already bounds the rate of change, so the MEMS model needs an amplitude clamp instead.

Four high-voltage channels, all resting at Vbias — that resting state is the mirror's origin. Each axis is a push-pull pair about that bias. Vendor's worked example: X+ at 110 V and X− at 50 V is "Vdifference of 60 V at Vbias of 80 V". Mirror rotation is approximately proportional to Vdifference.

Why the drive is differential

BDQ looks like extra complexity until you notice what it buys. An electrostatic actuator pulls with a force that goes as the square of the applied voltage — it can only ever attract, so a single-ended drive gives you one direction and a badly nonlinear one. Mounting two opposing actuators and driving them in push-pull about a common bias gives a signed deflection, and to first order the square-law terms of the two sides cancel, leaving the "approximately proportional" response the vendor documentation claims.

For reactoscope the useful part is that none of this is reactoscope's problem on the Analog Input driver. The BDQ circuit is inside the driver and its bias is not adjustable; the host hands over one bipolar, zero-centred voltage per axis and the driver synthesizes the differential high-voltage pair. It is the same division of labour as a balanced audio output — you present one signal, the receiving end deals in hot and cold.

Where that isn't true

On the Digital Input driver the host owns BDQ entirely, writing all four DAC channels over SPI, and the docs flag this as recommended only for users who already understand the methodology — the host becomes responsible for Vbias and Vdifference limits, and therefore for not destroying the mirror.

The bandwidth problem

This is the finding that decides what a MEMS emulator can honestly claim. The driver is specified at 50–25,000 Hz, which sounds like an audio device. But that figure is the ceiling with the filters bypassed; in normal operation the filter is set far lower, because its whole job is to keep drive content well below the mirror's mechanical resonance.

Where a quasistatic MEMS mirror sits against the audio band

The darker segment of the MEMS bar ends at 220 Hz — the cutoff actually hardcoded in LD_MemsMirror. The lighter segment extends to the 500 Hz the vendor guide uses in its worked example.

Put in terms that matter for drawing: a channel band-limited to 500 Hz cannot reproduce more than roughly 500 distinct direction changes per second. At 30 frames per second that is on the order of a dozen or so meaningful corners per frame; at 220 Hz, fewer still. A galvo laser projector is quoted in tens of thousands of points per second. The gap is not a tuning difference, it is a difference in what kind of image the device can draw at all — and it explains why essentially every repo in this survey that puts something on screen draws Lissajous figures or moves point-to-point slowly, rather than attempting vector artwork.

The one device here shaped like reactoscope's output

PlayzerX — Mirrorcle's own product — takes normalized [-1, +1] X/Y plus an 8-bit intensity value at up to 50,000 samples/second over USB. That is the shape of reactoscope's Master Output almost exactly, intensity channel included. Its documentation also states the failure mode directly: the mirror "is a high-Q spring-mass system, so large, rapid excursions can lead to ringing", mitigated but not eliminated by a low-pass filter on the controller. Few points at a high sample rate is the combination it warns about. That ringing is precisely the behaviour a MEMS Scanner Model exists to show.

Two implementation details worth stealing — and one bug

The Arduino driver writes DAC channels A, B and C with a write-only command and only the fourth with write-and-update-all, so all four high-voltage outputs step simultaneously. The Python driver uses write-and-update-immediately on every channel, so X+ moves before X− does; for a brief moment the pair is not balanced about the bias. At 220 Hz of filtering that transient is inaudible to the mirror, but it is the kind of detail that stops being free if anyone raises the cutoff.

The second is a genuine defect. Both over-range branches in MEMS_Control_Function.py call the recovery function with no arguments:

def Reset_AllBias(Voltage):      # requires a voltage
    ...

def Rotation_Control_X(Xbias, Xdiff, XdiffMax):
    if -XdiffMax <= Xdiff <= XdiffMax:
        ...
    else:
        print("Vdiff loaded Wrong")
        Reset_AllBias()          # TypeError — the safety path never runs

The guard correctly detects an out-of-range command, then raises TypeError instead of recentring the mirror. The protective branch is the one branch that was never exercised.

What this implies for a MEMS Scanner Model

The Galvo Scanner Model's shape — a second-order low-pass that is the mechanical response, followed by a slew clamp — does not transfer. In the quasistatic MEMS path the dominant filter is an electronic one placed deliberately in front of the mechanics, and its entire purpose is to make the mechanical response not show up. The mechanics only reappear when you push the cutoff toward resonance, which is exactly when the hardware is at risk.

StageGalvo Scanner Model (built)Quasistatic MEMS (proposed)
Limiting Slew clamp after the filter, fed back into filter state — models a torque/velocity limit Amplitude clamp before the filter — models a safe-angle voltage limit, which is where both libraries put it
Linear part 2nd-order biquad; parameters are bandwidth and damping 5th-order Bessel; the parameter is a cutoff, and it is a real dial on real hardware (FCLK ÷ 60)
Phase behaviour Resonant — overshoot and ringing are the point Linear phase by design — uniform delay, minimal overshoot, shape preserved
Mechanical resonance Is the model A second, optional high-Q stage that stays nearly silent until the cutoff is raised toward it
Why a rate limit exists Added explicitly, because a linear filter would price a long blank jump as free Falls out of the band limit — a 500 Hz-limited signal already has bounded slew

Sketched as a pipeline, the quasistatic model is clamp → Bessel lowpass → (optional resonator), against the galvo's biquad → slew clamp. Both sit behind the same Scanner Model seam and both turn commanded X/Y into actual X/Y, which is what makes them siblings rather than rewrites. The interesting product question is that the MEMS cutoff is a user-facing control with a physical meaning: raising it makes the drawing sharper and moves the device toward the regime its own vendor warns about. That tradeoff is visible, tunable, and genuinely the thing the emulator would be for.

If this ever leaves simulation

Three things in the docs are stated as hard preconditions, not advice. The filter clock must be running before anything else or outputs simply do not track. The bring-up sequence has the mirror connected last, after the four output voltages have been verified on a scope — and verified to have "smooth transitions, no steps/impulses/sharp edges". And the analog inputs want ±10 V, which is well above what a sound card produces, so a line output cannot be wired straight to a driver even though the signal convention matches.
